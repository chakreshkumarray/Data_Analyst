🔹 1. BASIC DATABASE QUESTIONS
❓ What is a Database?
A database is an organized collection of data that can be easily accessed and managed.

❓ What is DBMS?
DBMS (Database Management System) is software used to:
Store data
Retrieve data
Manage data
👉 Examples: MySQL, PostgreSQL, Oracle

❓ What is RDBMS?
Relational DBMS stores data in tables (rows & columns) and uses relationships.

❓ Difference: DBMS vs RDBMS
DBMS	RDBMS
No relations	Has relationships
Small systems	Large systems

🔥 🔹 TYPES OF RELATIONSHIPS
✅ 1. One-to-One (1:1)

👉 One record in Table A = One record in Table B

Example:
One person → One passport
Person	Passport
1	P101

✅ 2. One-to-Many (1:M) ⭐ MOST IMPORTANT

👉 One record in Table A = Many records in Table B

Example:
One customer → Many orders
-- customers table
id (PK)

-- orders table
customer_id (FK)

👉 Used in most real-world systems

✅ 3. Many-to-Many (M:M)

👉 Many records in Table A = Many in Table B

Example:
Students ↔ Courses

👉 Solution:
Use a junction table

Tables:
students
courses
student_courses (junction)


CREATE TABLE student_courses (
  student_id INT,
  course_id INT
);

Why the Relationship Model.

I. Data Integrity
II. Reduced Redundency
III. Flexibility in Querying

--- 2. SQL Basic ---
🔥 🔹 1. What is SQL?

SQL (Structured Query Language) is used to:
👉 Store, retrieve, and manage data in a database.

🔥 🔹 Main Categories of SQL Commands

SQL commands are divided into 5 main types 👇

✅ 1. DDL (Data Definition Language)

👉 Used to define or modify database structure

Commands:
CREATE → create table/database
ALTER → modify table
DROP → delete table
TRUNCATE → remove all data

Example:
CREATE TABLE employees (
  id INT,
  name VARCHAR(50),
  salary INT
);

✅ 2. DML (Data Manipulation Language)

👉 Used to work with data inside tables

Commands:
INSERT → add data
UPDATE → modify data
DELETE → remove data
Example:
INSERT INTO employees VALUES (1, 'Ram', 50000);

✅ 3. DQL (Data Query Language)

👉 Used to fetch data

Command:
SELECT
Example:
SELECT * FROM employees;

✅ 4. DCL (Data Control Language)

👉 Used to control permissions

Commands:
GRANT → give access
REVOKE → remove access
Example:
GRANT SELECT ON employees TO user1;

✅ 5. TCL (Transaction Control Language)

👉 Used to manage transactions

Commands:
COMMIT → save changes
ROLLBACK → undo changes
SAVEPOINT → temporary save
Example:
ROLLBACK;

--- 4. Basic Database Terminology ---

🔥 🔹 What is Schema?

A schema is the structure (design/blueprint) of a database.

👉 It defines:

Tables
Columns
Data types
Relationships
Constraints
📌 Simple Example
CREATE TABLE employees (
  id INT PRIMARY KEY,
  name VARCHAR(50),
  salary INT
);

🔥 🔹 1. Database Schema

👉 Definition:
A database schema is the overall structure of the entire database.

👉 It includes:

All tables
Relationships between tables
Constraints
Views, indexes
Example:

A company database may have:

employees table
departments table
orders table

👉 All of this together = Database Schema

🔥 🔹 2. Table Schema

👉 Definition:
A table schema defines the structure of a single table.

👉 It includes:

Column names
Data types
Constraints
Example:
CREATE TABLE employees (
  id INT PRIMARY KEY,
  name VARCHAR(50),
  salary INT
);

👉 This is the table schema of employees

🔥 🔹 3. Subschema (View Schema)

👉 Definition:
A subschema is a subset of the database schema that a specific user sees.

👉 It is used for:

Security
Simplicity
Custom views
Example:
CREATE VIEW emp_view AS
SELECT name, salary FROM employees;

👉 User sees only:

name
salary

👉 Not full table → this is subschema

🔥 🔹 What is an Index?

An Index is a data structure that:
👉 Speeds up data retrieval (SELECT queries)

👉 Works like:
📖 Index in a book → helps you find pages quickly

📌 Example

Without index:

Database scans all rows (slow)

With index:

Directly finds data (fast)
🔥 🔹 Syntax
Create Index
CREATE INDEX idx_name
ON employees(name);

🔥 🔹 What is a Query?

A query is a request to the database to get or manipulate data.

👉 In simple words:
Query = asking the database for information

📌 Example
SELECT * FROM employees;

🔥 🔹 What is a Result Set?

A Result Set is:
👉 The output (data returned) after executing a SQL query

📌 Example
SELECT name, salary FROM employees;
Suppose table:
name	salary
Ram	50000
Shyam	60000

🔥 🔹 Simple Meaning

👉 Query = Question
👉 Result Set = Answer

👉 Used to manage transactions

This is a very common interview question 👍
Let’s clearly understand DELETE vs TRUNCATE vs DROP 👇

🔥 🔹 1. DELETE

👉 Removes specific rows from a table

Features:
Can use WHERE condition
Deletes row by row
Can rollback (if transaction enabled)
Table structure remains
Example:
DELETE FROM employees
WHERE id = 1;
🔥 🔹 2. TRUNCATE

👉 Removes all rows from a table

Features:
No WHERE condition
Deletes all data quickly
Cannot rollback (generally)
Resets auto-increment
Table structure remains
Example:
TRUNCATE TABLE employees;
🔥 🔹 3. DROP

👉 Deletes entire table

Features:
Removes data + structure
Table is completely deleted
Cannot rollback
Need to recreate table
Example:
DROP TABLE employees;

--- 9. Where Clause ---

🔥 🔹 What is WHERE Clause?

👉 The WHERE clause is used to:
Filter records based on a condition

👉 It tells the database:
“Give me only the data that matches this condition”

📌 Basic Syntax

FROM table_name
WHERE condition;
🔥 🔹 Examples

✅ 1. Simple condition
SELECT * FROM employees
WHERE salary > 50000;

👉 Returns employees with salary > 50,000

✅ 2. Using AND
SELECT * FROM employees
WHERE dept = 'IT' AND salary > 60000;

✅ 3. Using OR
SELECT * FROM employees
WHERE dept = 'IT' OR dept = 'HR';

✅ 4. Using BETWEEN
SELECT * FROM employees
WHERE salary BETWEEN 40000 AND 80000;

✅ 5. Using IN
SELECT * FROM employees
WHERE dept IN ('IT', 'HR');

✅ 6. Using LIKE (Pattern Search)
SELECT * FROM employees
WHERE name LIKE 'A%';

✅ 7. Using NULL
SELECT * FROM employees
WHERE salary IS NULL;

🔥 🔹 Operators Used in WHERE
Type	Operators

--- 10. Logical Operator ---

🔥 🔹 What are Logical Operators?

👉 Logical operators are used in the WHERE clause to:
Combine multiple conditions

🔥 🔹 Types of Logical Operators
✅ 1. AND

👉 Returns TRUE if both conditions are true

Example:
SELECT * FROM employees
WHERE dept = 'IT' AND salary > 60000;

👉 Only employees who:

Are in IT
AND have salary > 60,000
✅ 2. OR

👉 Returns TRUE if any one condition is true

Example:
SELECT * FROM employees

👉 Employees in IT or HR

✅ 3. NOT

👉 Reverses the condition

Example:
SELECT * FROM employees
WHERE NOT dept = 'IT';

👉 Employees who are not in IT

🔥 🔹 Combined Example
SELECT * FROM employees
WHERE dept = 'IT' AND (salary > 50000 OR age < 30);

👉 Complex filtering using multiple operators

--- 17. Group By Having ---

🔹 1. GROUP BY

GROUP BY is used to group rows that have the same values in specified columns.

✅ Syntax:
SELECT column_name, AGGREGATE_FUNCTION(column_name)
FROM table_name
GROUP BY column_name;

SELECT department, COUNT(*) AS total_employees
FROM employees
GROUP BY department;

🔹 2. HAVING

HAVING is used to filter grouped data (after aggregation).

👉 Think:

WHERE → filters rows before grouping
HAVING → filters groups after grouping

✅ Syntax:
SELECT column_name, AGGREGATE_FUNCTION(column_name)
FROM table_name
GROUP BY column_name
HAVING condition;

SELECT department, COUNT(*) AS total_employees
FROM employees
GROUP BY department
HAVING COUNT(*) > 5;

18. Primary Key
---------------------------------------------------------------------------------------------------------
A Primary Key is a column (or combination of columns) that uniquely identifies each row in a table.

✅ Key Properties
Unique → No duplicate values allowed
Not NULL → Every row must have a value
Only one primary key per table
Can be single column or multiple columns (composite key)

🔹 1. Create Table with Primary Key

CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT
);

👉 id uniquely identifies each student.

🔹 2. Primary Key with AUTO INCREMENT
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50),
    age INT
);

👉 id will automatically increase (1, 2, 3, ...)

🔹 3. Add Primary Key to Existing Table
ALTER TABLE students
ADD PRIMARY KEY (id);
🔹 4. Composite Primary Key
CREATE TABLE orders (
    order_id INT,
    product_id INT,
    PRIMARY KEY (order_id, product_id)
);

19. Foreign Key
---------------------------------------------------------------------------------------------------

A Foreign Key is a column (or set of columns) in one table that refers to the Primary Key of another table.

👉 It is used to create a relationship between tables and maintain data integrity.

✅ Key Points

Links child table → parent table
Prevents invalid data (no orphan records)
Can have duplicate values
Can contain NULL (unless restricted)

🔹 1. Example (Basic)

👨‍🏫 Parent Table

CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(50)
);

👨‍💼 Child Table

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    emp_name VARCHAR(50),
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
);

20. 📚 Normalization in SQL
---------------------------------------------------------------------------------------------

Normalization is the process of organizing data in a database to:

Reduce redundancy (duplicate data)
Improve data integrity
Avoid anomalies (insert, update, delete issues)
🔥 Why Normalization?

Without normalization:

Same data repeats many times ❌
Updates become inconsistent ❌
Deleting data may remove important info ❌

🔹 Types of Normal Forms

------------------------------
✅ 1. First Normal Form (1NF)
------------------------------
👉 Rules:

No repeating groups
Each column has atomic (single) values

❌ Not in 1NF

id	name	phones
1	A	123, 456
✅ In 1NF
id	name	phone
1	A	123
1	A	456

-------------------------------
✅ 2. Second Normal Form (2NF)
-------------------------------

👉 Rules:

Must be in 1NF
No partial dependency (non-key columns must depend on full primary key)
❌ Problem:

If table has composite key:
| order_id | product_id | product_name |
👉 product_name depends only on product_id

✅ Solution:

Split into:

Orders(order_id, product_id)
Products(product_id, product_name)

❌ Table NOT in 2NF (Problem)

👉 Composite Primary Key = (order_id, product_id)

Orders Table (Before Normalization)
order_id	product_id	product_name
101	1	Laptop

⚠️ Problem Here
Primary Key = (order_id + product_id)

👉 So this table is NOT in 2NF

🚨 Issues
Data repetition (Laptop repeated multiple times) ❌

Inconsistency risk ❌

✅ 4. 🔄 Denormalization in SQL
---------------------------------
Denormalization is the process of combining normalized tables to improve read performance by reducing joins.

👉 Opposite of Normalization

🔥 Why Denormalization?
Faster read queries 🚀
Fewer JOIN operations
Useful in reporting systems / analytics
❗ Trade-off
Increases data redundancy ❌
Can cause update anomalies ❌
🔹 Example

✅ Normalized Tables (3NF)

Employees
emp_id	emp_name	dept_id
101	A	1
102	B	2
Departments
dept_id	dept_name
1	HR
2	IT
🔍 To Fetch Data (Normalized)
SELECT e.emp_id, e.emp_name, d.dept_name
FROM employees e
JOIN departments d
ON e.dept_id = d.dept_id;

👉 Requires JOIN

🔁 Denormalized Table
Employees_Details
emp_id	emp_name	dept_id	dept_name
101	A	1	HR
102	B	2	IT
🚀 Advantage
SELECT * FROM Employees_Details;

👉 No JOIN → Faster read

🚨 Disadvantages
Redundant data (HR repeated) ❌
If dept name changes → update multiple rows ❌
Risk of inconsistency ❌
🔥 When to Use Denormalization

✔ Read-heavy systems (dashboards, reports)
✔ Data warehouse
✔ Analytics queries

❌ When NOT to Use

❌ Transactional systems (banking, orders)
❌ Systems needing strict consistency

🔁 Normalization vs Denormalization
Feature	Normalization	Denormalization
Redundancy	Low	High
Performance	Slower (joins)	Faster (no joins)
Data Integrity	High	Lower
Use Case	OLTP systems	OLAP / reporting

-------------------------
1. Co-related Subquery
-------------------------
👉 Inner query runs for each row of outer query

Example:
SELECT e.name
FROM employees e
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
    WHERE dept_id = e.dept_id
);

👉 Compares employee salary with their department average

2. 🔹Scalar Subquery in SQL
------------------------------

A Scalar Subquery is a subquery that returns exactly one value (one row, one column).

👉 It behaves like a single value (constant) in a query.

✅ Key Points
Returns only 1 value
Used with operators like =, >, <
Can be used in:
SELECT
WHERE
HAVING
🔥 Example 1: Scalar Subquery in WHERE
SELECT name
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);

-----------------------
3. Exists
-----------------------

EXISTS is used to check whether a subquery returns any rows.

👉 It returns:

TRUE → if subquery returns at least 1 row
FALSE → if subquery returns no rows
🔹 Basic Syntax
SELECT column_name
FROM table_name t1
WHERE EXISTS (
    SELECT 1
    FROM table_name t2
    WHERE condition
);

✅ 23. UPDATE statement
--------------------------------------
An UPDATE statement in SQL is used to modify existing records in a table.

✅ Basic Syntax

UPDATE table_name
SET column1 = value1,
    column2 = value2
WHERE condition;

🔹 Example 1: Update a Single Row

UPDATE Employees
SET salary = 50000
WHERE emp_id = 101;

👉 This updates the salary of employee with emp_id = 101.

🔹 Example 2: Update Multiple Columns

UPDATE Employees
SET salary = 60000,
    department = 'IT'
WHERE emp_id = 102;

🔹 Example 3: Update Multiple Rows
UPDATE Employees
SET salary = salary + 5000
WHERE department = 'HR';

👉 Increases salary by 5000 for all HR employees.

🔹 Example 4: Update Without WHERE (⚠️ Dangerous)
UPDATE Employees
SET salary = 40000;

👉 This will update ALL rows in the table.

🔹 Example 5: Update Using Another Table (Subquery)
UPDATE Employees
SET salary = (
    SELECT AVG(salary)
    FROM Employees
)
WHERE department = 'Sales';
🔹 Example 6: Update with JOIN (MySQL)
UPDATE Employees e
JOIN Departments d
ON e.dept_id = d.dept_id
SET e.salary = e.salary + 2000
WHERE d.dept_name = 'IT';

24. Delete Statements
-----------------------------------------------------------------
🔥 DELETE vs TRUNCATE vs DROP

-----------------------
✅ 1. DELETE Statement
-----------------------

👉 Used to remove specific rows from a table.

🔹 Syntax
DELETE FROM table_name
WHERE condition;
🔹 Example
DELETE FROM Employees
WHERE emp_id = 101;

👉 Deletes only the employee with emp_id = 101.

⚡ Key Points
Can use WHERE ✅
Deletes row by row (slower)
Can be rolled back (if transaction is used)
Table structure remains

--------------------------
✅ 2. TRUNCATE Statement
--------------------------

👉 Used to remove all rows from a table quickly.

🔹 Syntax
TRUNCATE TABLE table_name;
🔹 Example
TRUNCATE TABLE Employees;

👉 Deletes all records instantly.

⚡ Key Points
No WHERE ❌ (removes everything)
Faster than DELETE 🚀
Cannot be rolled back (in most DBs)
Resets AUTO_INCREMENT value
Table structure remains

--------------------
✅ 3. DROP Statement
--------------------
👉 Used to delete the entire table (structure + data).

🔹 Syntax
DROP TABLE table_name;
🔹 Example
DROP TABLE Employees;

👉 Completely removes the table from database.

⚡ Key Points
Deletes data + structure
Cannot be rolled back ❌
Table no longer exists
🔥 Difference Table (Very Important for Interviews)
Feature	DELETE	TRUNCATE	DROP
Removes Rows	✅ Yes	✅ All	✅ All
WHERE Clause	✅ Yes	❌ No	❌ No
Speed	Slow	Fast 🚀	Very Fast 🚀🚀
Rollback	✅ Yes	❌ No	❌ No
Structure	Remains	Remains	❌ Deleted
Auto Increment	Not Reset	Reset	N/A

25. Replace Statement
-----------------------------------------------------------------------------------
🔥 REPLACE Statement in SQL

The REPLACE statement is used to insert a new row or update an existing row if a duplicate key is found.

👉 It works like:
INSERT + DELETE + INSERT (internally)

✅ Syntax
REPLACE INTO table_name (column1, column2, ...)
VALUES (value1, value2, ...);
🔹 Example Table
Employees(emp_id, name, salary)
🔹 Example 1: Insert New Row
REPLACE INTO Employees (emp_id, name, salary)
VALUES (101, 'Amit', 50000);

👉 If emp_id = 101 does NOT exist → it will INSERT.

🔹 Example 2: Replace Existing Row
REPLACE INTO Employees (emp_id, name, salary)
VALUES (101, 'Amit', 60000);

👉 If emp_id = 101 already exists:

Old row is deleted
New row is inserted
⚡ Important Points
Works only when:
Table has PRIMARY KEY or UNIQUE KEY
If duplicate key found:
Old row is deleted ❌
New row inserted ✅
If no duplicate:
Normal INSERT happens
